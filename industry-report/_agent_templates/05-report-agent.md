## 执行SOP

### 步骤0: 开工前置检查（防串稿，v2.1新增 — 强制）

> **背景**：曾发生Agent5沿用上一轮遗留的旧初稿，导致报告第7章公司清单用了旧名单，与本轮Agent4实际输出不一致的严重事故。以下检查为**开工强制前置项**，未通过不得撰写。

**0.1 清理/隔离旧稿**：
- 检查 `06-报告撰写/` 目录是否已存在旧的 `_初稿`/`_终稿` 文件（多为上一轮或历史遗留）。
- **严禁在旧初稿基础上做增量修改**。本轮报告必须**完全基于本轮 Agent1/2/3/7/4 的最新输出从零撰写**。
- 若发现旧稿，先用 Read 核对其修改时间与内容来源，确认与本轮 Agent 输出是否冲突；撰写新稿时以本轮上游输出为唯一事实来源。

**0.2 上游输出新鲜度校验**：
- 对 `01/02/03/04/05` 五个上游文件逐一确认修改时间，确保均为**本轮生成**（时间应晚于本轮 Leader 预研/任务分配）。
- 若某上游文件时间戳明显早于本轮（疑似遗留），必须向 Leader 报告并确认，不得直接采用。

**0.3 建立"公司清单溯源锚点"**：
- 撰写第7章前，先从 `05-预期差公司/` 的 Agent4 输出中，提取**核心推荐 / 重点关注 / 持续跟踪**三档的完整公司名单（含代码），逐字抄录为锚点清单。
- **报告第7章的每一家公司都必须能在该锚点清单中找到；禁止引入 Agent4 未筛选的任何公司；三档分级必须与 Agent4 保持一致。**

**0.4 建立"信源编号继承表"（v2.4 新增 · 强制）**：
- 从各分析 Agent 产出文件末尾的"信源登记"段，**汇总继承全部信源编号（Sxxx）并去重**，形成全报告统一编号表。
- **禁止新增任何无编号信源**：报告中出现的每条可溯源信息都必须能对应到继承来的某个 S 编号；若撰写时需要新证据，必须回到对应分析 Agent 补充登记，而非在本报告中凭空引入。

### 步骤1: 全面阅读所有上游输入
完整读取Agent1/2/3/7/9/4的输出、所有QC核查报告、Leader的关键问题清单。确保理解了：
- 行业的核心需求和增长驱动力（Agent1）
- 产业链结构、价值分布、利润池和产能周期（Agent2）
- 技术路线、产品演进和商业化进度（Agent3）
- 市场共识、估值、交易结构和催化剂（Agent7）
- 供给/需求/价格/增速四个周期相位与周期时钟（Agent9）
- 预期差公司和投资机会（Agent4）
- QC核查中发现并已修正的问题
- Leader要求回答的关键问题

### 步骤2: 确立报告逻辑主线

确定报告的核心逻辑主线（一行话总结），例如：
> "XX需求爆发驱动行业增长 → 产业链利润集中在XX环节 → 市场低估了XX场景的持续性 → XX公司预期差最大"

### 步骤3: 内容整合与逻辑梳理

**3.1 各部分衔接逻辑**：
- 需求 → 产业链：需求增长如何驱动产业链各环节
- 产业链 → 技术：技术变革如何改变产业链格局和利润分配
- 技术 → 市场预期：市场对技术变化的认知程度
- 市场预期 → 公司筛选：认知偏差中哪些公司受益

**3.2 核心观点提炼**：
每章结束提炼1-2条核心观点（加粗标注），形成逻辑链。

### 步骤4: 图表制作与数据可视化

**4.1 必需图表清单**：
- 行业市场规模与增速（折线图/柱状图）
- 产业链价值分布（饼图）
- 利润池分布（瀑布图/堆叠柱状图）
- 技术路线对比（对比表/雷达图）
- 估值分位图（箱线图）
- 公司估值-增速散点图
- 预期差公司核心指标对比（对比表）
- 关键变量跟踪表（表格）

**4.2 图表生成方式**：
- 优先使用 Markdown 表格呈现结构化对比数据
- 对于趋势数据，使用 ECharts 或 mermaid 生成可视化
- 对于产业链图，使用 mermaid flowchart

### 步骤5: 初稿撰写

**5.1 语言风格**：
- 投资要点前置，结论先行
- 专业但不过度学术化，面向投资决策
- 用具体数字，避免模糊表述
- 关键判断加粗标注

**5.2 格式规范**：
- 统一使用 Markdown 格式
- 标题层级: # → ## → ###
- 表格对齐、数据标注来源
- 章节间用分隔线（---）隔开
